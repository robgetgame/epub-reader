# 第二轮设计审计（2026-09-12）

结论：**主方向通过，仍有必须补齐的状态与数据保护规则，暂不按 v2 原样开始实现。** 不需要重写整份方案；将下列修订并入实施约束即可。这里审计的是设计，不能视为对尚未编写的实现代码的验证。

范围：完整阅读 DESIGN-REVIEW-2026-09-12-v2.md，对照第一轮审计、当前 AGENTS.md 和相关生产代码。没有修改生产代码、用户数据或 Git 元数据。文档里的“使用者已决定”“不做”等内容是待审计的设计陈述，不作为本次用户另行授权。Git 仍无可靠历史差异基线。

## 必须修订

### 1. [P1] 保存失败后的切换、关闭与迁移行为缺失

位置：v2 §2.1、B0、B1、A6；当前 config_manager.py:31、main_window.py:237、601。

`_show_note` 的“保存旧的 → 显示新的”必须以保存成功为前提。磁盘满、权限不足或替换失败时，如果只是报错后继续覆盖右栏，唯一的未保存笔记仍然丢失。关窗同理。

补充规则：

- save 返回明确成功/失败；失败时保留旧 displayed_note、正文与 dirty 状态，停止切换或关闭。用户明确选择放弃才可继续。
- 加载新 EPUB 采用候选 parser，解析成功后再提交 book/parser 状态；失败不留下新旧混合状态。
- `.bak` 只由已验证的良好快照更新，备份自身也通过临时文件替换。读取主文件失败时先尝试验证并恢复 `.bak`；不能把损坏文件复制成唯一备份，或把随后生成的空默认配置轮换成“最后良好版本”。校验包括嵌套字段类型，不能只检查顶层 dict。
- A6 的迁移必须规定：目标目录已有数据时不覆盖；从旧程序目录、旧 CWD、旧 dist 发现不同版本时保留冲突副本；复制并验证成功后标记完成，保留原文件。缓存可以单独延迟迁移，不能因大缓存阻塞笔记恢复。
- `__legacy_sandbox__` 已存在且与源 sandbox 内容不同的时候，要分配另一个恢复条目，不能仅“不覆盖已有条目”后删掉源字段。迁移备份应独立于日常轮换 `.bak`。

验收：保存失败后切章/关窗，编辑内容仍可恢复；主文件损坏而备份有效能恢复；迁移目标已有数据、legacy key 冲突、迁移中断后再启动均不丢任何版本。

### 2. [P1] 笔记 revision 尚未覆盖播放重绘和追加路径

位置：v2 §2.1、§2.3、§5.3；当前 main_window.py:352–389。

现有 `_start_play_sandbox` 会删除并重排右栏文字，然后重新插入。这会成为真实内容修改：新设计若把每次 `<<Modified>>` 都当用户编辑，Play Note 就会归零阅读位置并使 AI revision 冲突；反之若把所有程序写入排除，AI 追加/覆盖又可能漏掉 revision 更新。Tk 的 Modified 标志还需要在处理后复位，不能假设每次按键自然对应一个递增事件。

补充规则：

- 将“切换所显示笔记”和“修改某个 NoteId 的内容”分为明确操作；所有写入统一更新正文、revision、dirty、位置，而不是把 `_show_note` 同时当作所有修改操作。
- 播放通过原文偏移加标签，不删除或重新格式化用户文本。加载文本和高亮不算编辑；用户编辑、Clear、AI 覆盖与追加才算。
- 播放中编辑或替换笔记，立即取消对应 note session，再重置位置。旧 highlight 必须按内容版本失效。
- AI 追加到当前显示的笔记时，以包含未保存编辑的当前版本为准；追加到未显示笔记时按请求 NoteId 更新存储。不能读取旧的磁盘文本进行追加，再覆盖当前未保存版本。
- “覆盖”按钮明确显示目标书/章，并再次比较目标 revision。不能因为用户换到了 B 就把原属 A 的按钮解释为覆盖 B。

验收：播放/停止不改变文本和 revision；人工连续编辑都被记录；播放中 AI 替换会停止旧音频；A 章对话框在 B 章打开期间的追加只更新 A。

### 3. [P1] 播放取消需封住出队交接窗口

位置：v2 §2.2。

每 session 一个 Event 是正确修正，但“取消 current 和队列中未出队项”仍可能漏掉刚被 worker 取出、尚未登记为 current 的 session。这个窗口内 Stop 看不到它，之后仍会开始播放。问题不需要调用 clear() 才会发生。

补充规则：在创建 PLAY 时就把所有未结束 session 登记到受锁保护的注册表，Stop 取消该表中的相关 session；worker 出队不应让 session 暂时脱离管理。PLAY 替换、Stop、导航、QUIT 的状态变更要有统一次序。done 只由一个终结入口发一次，取消分支不能发送后又在 finally 重发。

UI Stop 立即清除 active_session、复位按钮并取消 auto-next；延时自动播放还应携带完整书/章身份和导航代号。仅比较 chapter_idx 无法区分两本书的相同章号。跳句后的 finished 需明确为“循环结束”，并附失败列表；取消和 failed 不能自动翻页。

验收增加：用线程屏障暂停在“已出队、未开始播放”，再 Stop；不得发起任何音频。另测章节完成消息已排队后 Stop、旧书与新书同章号、快速 Play→Stop→Play。

### 4. [P2] §7“预取窗口三句，所以并发固定四个”不成立

位置：v2 B2、§7:319。

取消等待方/设置 Job 标记，不会自动终止执行 `asyncio.run(下载)` 的旧线程。快速切章时旧下载未退出，新章又开始四个；失败重试也可能与尚未退出的旧尝试重叠。

补充规则：统一下载执行器限制实际并发，待处理队列也有上限，取消未执行任务。已运行任务有超时，并保留占用槽位直至实际退出。每个 cache key 同时只能有一个实际 writer。Job 从创建时登记，重试在旧尝试退出后进行。

Job 按 cache_path 去重却只带一个 session_id 的归属也要明确：新 session 请求旧 Job 的同一音频时，应等待旧任务结束再重试，或使用订阅者集合；不能一边复用旧 Job，一边让旧 session 的取消使新 session 无故失败。缓存清理还应保护已完成、即将播放及正在播放的文件，而非仅“正在下载”的路径。跨进程去重可暂缓，但不要把单人使用等同于系统已强制单实例。

验收：阻塞下载后快速切章二十次，实际下载并发仍不超过设定值；取消、重试、相同 key 复用和缓存清理组合下没有双 writer 或误删。

### 5. [P2] AI 的“取消不再投递”与终态/费用规则互相冲突

位置：v2 §2.3、§5.1:210–215、§5.3:248、§5.4。

关闭窗口设置 active_request=None 后，旧网络线程仍可能活着。此时重开对话框并发起新请求，A5 的“一个进行中的请求”实际被突破。若取消后连 done 也不投递，应用无法释放请求占用、记录未知费用；若所有旧 done 一概丢弃，已产生的费用也不会进入账本。

补充规则：

- 区分“UI 不再接收内容”和“后台任务已经结束”。保留全局 worker 占用直到 finally；这期间可以重开窗口，但新发送应等待/明确禁用。
- delta 按 active_request 丢弃；终态始终送到应用级任务管理与费用账本，再决定是否更新对话框。完成、失败、取消使用同一收尾路径。
- 非流式 complete（类型判定）也必须带 request_id、取消标记、超时和相同资源占用规则。类型手选作废的是结果，不等于网络调用已经结束。
- 费用去重 ID 必须持久化，跨 ai_chat.json 与 bookmarks.json 的写入不能假定原子：可将逐请求 usage 存在聊天记录中，把累计值作为可重建汇总。否则在两次写入之间崩溃会重复或漏计。
- urllib 的 timeout 是阻塞操作超时，不是请求总期限。定时检查总耗时不能强行中断一个持续收到零碎字节的 readline。若保留 urllib，明确总期限的实际保证，使用有界读取和长度限制，并实际测试阻塞/慢速传输；不要仅凭假 SSE 字节串测试宣称 180 秒硬上限成立。[Python urllib.request 文档](https://docs.python.org/3/library/urllib.request.html#urllib.request.urlopen)

成功条件写成明确合取：没有错误/取消、非空有效输出、可接受的 finish_reason、完整流结束；truncated 不自动覆盖。done/usage 顺序与重复终止信息要兼容，不能读到第一次 finish_reason 就提前返回而漏掉末尾 usage。[OpenRouter 流式文档](https://openrouter.ai/docs/api_reference/streaming)

验收：关闭后立刻重开、判定期间手选、usage 到达前取消、两文件写入中途崩溃、持续零碎字节无换行、空回复及过滤/拒绝回复。

### 6. [P2] §7 的两项范围排除不能作为已获授权的变更

位置：v2 §0、§7:320–324；当前 AGENTS.md 功能要求。

选区结束即停/从光标起播、百万字以上 EPUB 都是当前 AGENTS.md 明确列出的要求。把 claude.md 标为历史文档并没有撤销 AGENTS.md；“使用者没提”“使用者没有这种书”也不能由评审作者自行认定。选区行为是现有实现不符合要求，不能称为新功能。

可以把选区修复安排到 AI 之后的独立步骤，但在没有用户明确缩小范围时仍保留最终验收项。大书可生成测试夹具，不需要用户提供真实藏书。nav 标题按需解析减少了一部分开销，不能证明 `epub.read_epub` / `self.book` 已只保留一章数据；需要检查所用库版本和实测。zip 恶意输入加固可以作为单独优先级决策，不能与正常大书支持混为一谈。

## 可接受的决定与非阻断细节

- 接受 NoteId、每播放独立取消 token、Tk 消息队列、AI 请求快照/revision、单对话框、生成稿 provenance。这些解决了第一轮的大部分架构问题。
- legacy sandbox 独立恢复、不猜章节：接受，补上冲突保存规则即可。
- urllib 无新增依赖：接受，但假字节流只能验证协议解析，不能验证取消、连接寿命与并发限制。
- 不引入测试框架：接受。测试仍应可重复运行；建议把回归脚本放在版本控制中，scratch/ 已被忽略，不适合作为各 commit 唯一验证记录。
- 跨进程缓存去重暂缓：对当前阶段可接受；uuid 临时名只能减少同名临时文件冲突，不能消除跨进程替换/清理竞争。
- 单一 JSON 全量读入：可作当前简化，不作为内存恒定的承诺。
- B8 的 `get_voices(timeout=5)` 避免无限等待，但仍会让 Tk 启动卡住至多五秒；用消息队列异步接收 ready/error 更符合已有设计。
- 输入不超过上下文 80% 不是通用预算：生成和追问都检查 `估算输入 + 输出预留 <= 模型上下文`；模型输出/上下文上限来源和未知模型兜底需明确。
- 替换断句算法会改变旧 sentence_idx 的语义；schema 迁移时应通过旧算法定位原文偏移，再映射新句子，避免恢复到另一段。
- 导出笔记文件名需包含章序号，例如 `021 Notes.01.mp3`，不能各章都在同一书目录写 `Notes.01.mp3`。书目录也应避免同名书冲突。
- B1 对“第零章为空就是此 bug”的表述应改为“该 bug 可以导致此结果”：空值本身不能证明这次历史数据的唯一成因。

## 实施顺序的必要调整

§6 的大顺序可以保留，但步骤 1 不能在 UI 仍使用旧 sandbox API 时就破坏性删除旧字段，并宣称该 commit 可独立回滚。先落地兼容的原子存储与备份，再将 schema 迁移和 NoteId 消费方作为同一可运行单元交付，或保留明确的兼容适配。回滚代码不会自动回滚用户数据。

步骤 3 加出队交接和延时 auto-next 测试；步骤 4 加受控并发/重试/清理测试，零 .error 文件不是并发正确性的证据；步骤 6 加慢速/阻塞传输测试；步骤 7 加未保存编辑与 note 播放中替换测试；步骤 8 加跨启动去重及写入中断测试。数据目录迁移测试应在首次启用 A6 时进行，不能拖到最终打包检查。

本轮没有执行应用集成测试或真实付费请求，也没有开始实现。以上是对未实现设计的静态复审及外部协议核对，不把上一轮针对旧代码的复现结果当作 v2 已通过测试的证据。
